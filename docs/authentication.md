# Authentication

Sanctum provides stateful first-party cookie authentication and store-scoped bearer tokens. Authentication REST routes live in `Modules/Authentication/routes/api.php`; GraphQL does not expose login or token mutations.

Registration creates a normalized lower-case email, global user, store, active membership, and `Owner` role in one transaction. Entity tables use internal bigint IDs and public ULIDs. `Registered`, `StoreCreated`, and verification notification work run after commit. Login uses the `web` session guard and regenerates the session. Token login requires a Store ULID and an active membership, stores the internal bigint `store_id` plus only the Sanctum hash, and returns the plain token once. A token bound to one store cannot be used with another `X-Store-ID`. Migrated tokens retain a private nullable `legacy_id` only so already-issued UUID-prefixed bearer credentials continue to resolve; APIs never serialize it.

Password reset uses Laravel's broker and queued JSON notifications with a configured frontend reset URL. Email verification uses the User ULID in a temporary signed URL and returns JSON. Logout invalidates the session for cookies or revokes only the current bearer token. Super-admin access is global and represented by the platform-scoped `Super Admin` role; a store header can never grant it.

Platform `Super Admin` users manage Platform staff through `/api/v1/platform/users` with `manage platform users`. Creation requires one or more existing Platform roles and cannot assign Store roles. Merchant and Store-user provisioning create `scope = store` identities through Stores-owned services; Authentication supplies the identity model, role catalog, validated assignment service, registration event, and verification notification. See [User and merchant management](user-merchant-management.md).

Required environment values include `FRONTEND_RESET_PASSWORD_URL`, `FRONTEND_EMAIL_VERIFIED_URL`, `SANCTUM_STATEFUL_DOMAINS`, `SESSION_DOMAIN`, CORS origins, and mail settings. Optional local-only account fixtures use the empty variables documented in `.env.example`; credentials stay in ignored `.env`. Never put credentials or real reset links in source control.
